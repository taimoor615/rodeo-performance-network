Point 16 Team Roping Handicap Divisions Session 1
PDF Status
Not in PDF

Team roping is covered in Sections 6.2 and 6.5 (pages 13–15) but only discusses Header/Heeler roles and completion status. The handicap division numbering system (#7.5–#15.5, Open) is new client feedback, not in the original specification.

Background — How Roping Divisions Work
  • Each roper (header and heeler) has an individual skill number (#3 beginner to #9/#10 professional)
  • The combined number (header's # + heeler's #) determines which division they can enter
  • Example: a #6 header + #5 heeler = combined #11 → qualifies for #10.5–#11.5 division
  • Open division has no combined cap
What Was Done
  • Added a TEAM_ROPING_DIVISIONS constant with the client-provided division structure
  • Team Roping – Header and Team Roping – Heeler now show these divisions in both forms
  • A hint appears: "Combined header + heeler handicap number. Open = no cap."
Division Structure
DivisionLevelNotes
OpenEliteNo age or handicap cap, for high-level ropers
#14.5 – #15.5AdvancedHigh-numbered, often with Slide formats
#12.5 – #13.5MidMid-level, often age restricted (21+)
#10.5 – #11.5Lower-midOften capped heeler max
#7.5 – #9.5Beginner–IntermediateStrict caps on both header and heeler

Point 20 — New Earnings / Payout Input Fix Session 2
PDF Status
In PDF

Section 4.5 (page 10) mentions prize money / payout as a recorded data field for performance entries. The bug where the input refused entry is not in the specification — it is a browser behavior issue with type="number" inputs in React.

Why This Bug Occurred

type="number" in React controlled components can show a browser validation popup ("Please enter a number") even when the value is a valid number string — especially on initial render with an empty string value or after certain state updates. This is a known cross-browser quirk with controlled React inputs.

What Was Done

Changed the Payout / Prize Money input from type="number" to type="text" with inputMode="decimal" in three places:

#LocationForm Step
1Rider Post Score — RoughstockStep 5 — Placement & Payout
2Rider Post Score — TimedStep 4 — Placement & Payout
3Organizer Submit ResultsPayout ($) field

The submit handlers already used Number(value) to convert to a number before sending — no change was needed there. inputMode="decimal" preserves the numeric keyboard on mobile while removing the problematic browser validation on desktop.

Point 21 — New Team Roping — Slide Division Added Session 3
PDF Status
Not in PDF

Team roping divisions are covered in Sections 6.2/6.5 but the Slide format is not mentioned. This is new client feedback based on WSTR (World Series of Team Roping) format data.

Background — What "Slide" Means
  • A Slide event is a handicap bracket format used by major associations like WSTR
  • It raises the combined number cap beyond the standard range (above #13.5 or #15.5)
  • Acts as a handicap bracket so higher-skilled teams compete against each other fairly
  • Sometimes includes time adjustments so differently-matched teams remain competitive
What Was Done
  • Added #15.5 Slide between Open and #14.5–#15.5 in the division list
  • Added #13.5 Slide between #14.5–#15.5 and #12.5–#13.5
  • Updated hint text to explain Slide format
  • Both rider Post Score and organizer Submit Results forms show the updated options

#14.5 – #15.5StandardHigh-skill range
#13.5 SlideSlideRaised cap — WSTR handicap bracket
#12.5 – #13.5StandardMid-level, often age restricted
#10.5 – #11.5StandardLower-mid, capped heeler
#7.5 – #9.5StandardBeginner to intermediate

Point 22 — New Goat Tying — Correct Youth Divisions Session 3
PDF Status
Not in PDF

The client confirmed goat tying is a youth sport — divisions should be age/grade based, not the 1D–5D time-spread system used in barrel racing.

Background
  • Goat tying is a youth sport — competitors are Junior High, Senior High, or College level
  • The 1D–5D system (previously applied) is for barrel racing and splits entrants by proximity to the fastest time — this does not apply to goat tying
  • Goat tying divisions reflect competitor age/grade, not their time bracket
Goat Tying Scoring Rules (Client Confirmed)
RuleHow the App Handles It

5-sec penalty if horse crosses ropePENALTY_VALUE['Goat Tying'] = 5, num_penalties field
3 legs tied with piggin' string + hooeyRules knowledge — not tracked in score form
What Was Done
  • Added new GOAT_TYING_DIVISIONS constant: Junior High, Senior High, College, Open
  • Removed Goat Tying from the 1D–5D barrel racing group in getDivisionsForEvent()
  • Goat Tying now returns its own youth divisions instead of 1D–5D
  • Updated hint text: "Youth event — select your age division. 5-sec penalty if horse crosses the rope."
  • Existing scoring logic (5-sec penalty, no-time) unchanged — already correct
